# موتور کاراکتر (فاز ۳، آماده‌سازی فاز ۵)

این سند قرارداد `kimia::CharacterMotorComponent` است: «راه رفتن» به‌عنوان
**دادهٔ روی موجودیت**، نه یک عدد جهانی و نه رفتار سخت‌کدشده در کنترلر.

---

## ۱. مسئله

سه چیز هم‌زمان غلط بود:

1. **یک سرعت برای همه.** `PlayerConfig::speed` (منوی کند/معمولی/تند ویرایشگر)
   تنها عدد حرکت در کل دنیا بود. دو بازیکن نمی‌توانستند سرعت‌های متفاوت
   داشته باشند، چون «سرعت» ویژگی دنیا بود نه ویژگی بازیکن.
2. **جهش سرعت.** `PhysicsWorld::moveCharacter` سرعت افقی را مستقیم از
   ورودی می‌گیرد؛ یعنی در همان فریمی که کلید را می‌زنی با سرعت کامل راه
   می‌روی و در همان فریمی که رها می‌کنی می‌ایستی. برای یک بازی فوتبال این
   «تلپورت» است، نه راه رفتن — و فاز ۵ (انیمیشن) هیچ سیگنال واقعی‌ای برای
   شتاب‌گرفتن و شتاب‌ازدست‌دادن ندارد.
3. **پرش یکی برای همه.** ارتفاع پرش از پروفایل بازی می‌آمد، پس هر کاراکتر
   یکسان می‌پرید.

## ۲. قرارداد

```cpp
struct CharacterMotorComponent {
  f64 maxSpeed = 4.0;        // m/s روی زمین (سرعت «معمولی» موتور)
  f64 acceleration = 24.0;   // m/s^2 به‌سوی سرعت هدف، هم برای تندشدن هم ایستادن
  f64 airControl = 0.25;     // کسری از acceleration که در هوا هست
  f64 jumpSpeed = 4.9;       // m/s در لحظهٔ کنده‌شدن؛ ۰ = نمی‌تواند بپرد
  f64 turnRate = 12.0;       // rad/s چرخش بدن به‌سوی جهت حرکت؛ ۰ = فوری
};
```

قواعد:

* **حضور موتور بر منوی سرعت دنیا مقدم است** — همان قاعدهٔ بقیهٔ کامپوننت‌ها:
  نام هنوز کار می‌کند، کامپوننت بازنویسی می‌کند.
* **موتورِ موجودیت «Player» سرعت دنیا را هم می‌نویسد.** قدرت شوت، سرعت
  دریبل و سرعت بستن حریف‌ها همه با همان یک عدد تنظیم شده‌اند؛ بازیکنی که با
  نصف آن راه برود دارد بازی دیگری بازی می‌کند. پس یک عدد وجود دارد و منوی
  کند/معمولی/تند آن را می‌نویسد (`setPlayerPace`) — چه موتور باشد چه نباشد.
* **`acceleration = 0` یعنی رفتار قدیم، مو‌به‌مو.** بدون موتور هیچ‌چیز عوض
  نمی‌شود: `moveCharacter` همان‌طور که بود سرعت را مستقیم می‌گیرد. این
  عمدی است؛ هر دنیای ساخته‌شده باید همان حسی را بدهد که با آن ساخته شده.
* **`jumpSpeed = 0` یعنی نمی‌تواند بپرد**، حتی اگر پروفایل پرش داشته باشد.
  موتور اینجا هم مقدم است. فرمول ارتفاع همچنان مال فیزیک است
  (`characterJumpSpeed` سرعت را می‌گیرد و `v = sqrt(2gh)` را وارونه نمی‌کند؛
  همان انتگرال گرانش جواب می‌دهد).
* **چرخش بدن حالت (state) است، نه یک تابع لحظه‌ای.** با موتور، `squadFacing`
  برای کاراکتر اصلی جهتی را برمی‌گرداند که در فریم‌های قبل با `turnRate`
  ساخته شده؛ ایستاده هم همان جهت می‌ماند (آدم وقتی می‌ایستد نمی‌چرخد).
  بدون موتور، مثل قبل: جهت، همان جهت سرعت است و ایستاده، جهت نشانه‌گیری.

## ۳. فایل (SceneIO v3)

کلیدواژهٔ `motor <speed> <accel> <air> <jump> <turn>` در **نسخهٔ ۳** فرمت
اضافه شد. چرا نسخهٔ تازه و نه یک کلیدواژهٔ دیگر در v2؟ چون موتور رفتار را
عوض می‌کند: موتور قدیمی‌تر که v2 را می‌خواند، این فایل را می‌پذیرد، کلیدواژهٔ
ناشناخته را دور می‌ریزد و کاراکتر را با سرعت دنیا راه می‌برد — **بدون اینکه
بگوید**. نسخهٔ ۳ دقیقاً همان سکوت را غیرممکن می‌کند
(`scene file version 3 is newer than this engine understands (2)`).

نویسنده **قدیمی‌ترین** نسخه‌ای را می‌نویسد که صحنه را بیان می‌کند: صحنهٔ بدون
id و بدون موتور همان v1 بایت‌به‌بایت قبل است. `versionFor()` در SceneIO.cpp
جدولی است از «هر ویژگی، نسخهٔ خودش»؛ ویژگی بعدی یک خط اضافه می‌کند، نه یک
شمارهٔ تازه برای همهٔ فایل‌ها.

**معنای `migrated`.** از این نسخه به بعد `migrated` یعنی «بارگذاری مجبور شد
چیزی بسازد که فایل نداشت» (فایل v1 که id ندارد و اینجا شماره گرفت، یا id
تکراری که تعمیر شد) — نه «نسخه‌اش از kVersion قدیمی‌تر است». با فرمتی که هر
ویژگی نسخهٔ خودش را دارد، فایل v2 در موتور v3 هیچ مهاجرتی نیست: همهٔ چیزی که
به کار می‌برد سر جای خودش خوانده می‌شود.

## ۴. ویرایشگر

* `WorldEditor::setEntityMotor(name, motor)` / `clearEntityMotor(name)` /
  `characterMotor(name)`.
* `setPlayerPace(speed)` / `playerPace()`: یک عدد برای منو و پاها.
* مسیر HTTP: `/api/fit-motor?name=Player&speed=6&accel=30&air=0.2&jump=5.5&turn=9`
  و `/api/fit-motor?name=Player&clear=1`. هر پارامتری که نیامده باشد، پیش‌فرض
  خودِ کامپوننت را نگه می‌دارد.
* `dossierJson` موتور را به‌صورت `"motor": {...}` یا `null` می‌دهد، پس Bench
  می‌تواند آن را نشان دهد.

## ۵. تست‌ها

* `sceneio_character_motor_is_a_v3_file_and_roundtrips` — سرصفحه v3، خط
  `motor`، و برگشت کامل هر پنج عدد.
* `sceneio_v3_is_only_written_when_a_motor_needs_it` — سوراخ‌ها → v2، موتور
  → v3، موتور با دسته‌های ۱..N → v3 **بدون** `id` (تستی که یک باگ واقعی را
  گرفت: `withIds` از نسخه مشتق شده بود، پس هر فایل v3 بی‌دلیل `id` می‌نوشت).
* `sceneio_an_incomplete_motor_line_is_dropped_with_a_warning` — «موتور
  نیمه» یک کاراکتر با سرعتی است که کسی انتخاب نکرده؛ خط کامل رد می‌شود.
* `worldio_reports_a_scene_from_a_newer_engine` — v7 رد می‌شود و پیام شمارهٔ
  نسخهٔ همین بیلد را می‌گوید؛ v3 پذیرفته می‌شود.
* `character_motor_sets_the_pace_and_the_ramp` — یک فریم ۰٫۰۶۶۷ m/s است نه
  ۲، توقف هم رمپ است، منوی سرعت موتور را می‌نویسد، و برداشتن موتور رفتار را
  به «یک فریم = سرعت کامل» برمی‌گرداند.
* `character_motor_owns_the_jump` — سرعت کنده‌شدن بیشتر ⇒ اوج بالاتر، و
  `jumpSpeed = 0` ⇒ پرش ممنوع حتی با پروفایلِ پرش‌دار.
* `world_without_a_motor_moves_exactly_as_before` — رگرسیون رفتار قدیم.
* `world_file_carries_the_motor` — WorldIO: موتور و سرعت دنیا با هم می‌روند و
  با هم برمی‌گردند.

نکتهٔ اندازه‌گیری: بعد از هر تلپورت (`setPlayerPosition`، `resetCharacter`)
کاراکتر یک فریم `onGround = false` است، پس آن یک فریم با `airControl` شتاب
می‌گیرد. تست‌ها اول یک فریم می‌نشانند و بعد شیب زمینی را اندازه می‌گیرند.

## ۶. چه چیزی هنوز نیست

* **پرش فعال نیست** (`jumpSpeed` فقط در لحظهٔ کنده‌شدن اثر دارد): کوک کردن
  پرش در هوا، کوییک‌جایی و «کوییک‌فال» فاز ۵ است.
* **`turnRate` روی انیمیشن اثر ندارد**: فعلاً فقط جهت بدن را عوض می‌کند.
  انیمیشن چرخش (Turn State) فاز ۵ است.
* **گام (step offset) و شیب** در کنترلر کاراکتر نیستند؛ آن‌ها فاز ۴ هستند و
  موتور جای پارامترهایشان را دارد.
