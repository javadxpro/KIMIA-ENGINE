# AssetManager — کش دارایی

این سند قرارداد `kimia::AssetManager` است: تنها جایی که دارایی از دیسک
خوانده می‌شود. حلقهٔ فریم هیچ‌وقت خودش فایل باز نمی‌کند.

---

## ۱. چرا

حلقهٔ فریم `Examples/WorldEditorApp.cpp` تا دیروز دو `std::map` دست‌ساز
داشت (`loadedMeshes` و `loadedTextures`) و در چند نقطهٔ مختلف خودش
`assets::loadMesh` / `loadMeshAsset` / `loadImage` صدا می‌زد. نتیجه:

- مسیر فایل در سه جا با سه قاعدهٔ متفاوت resolve می‌شد و **رد شدن**
  فایل هیچ‌جا گزارش نمی‌شد؛ مدل گم‌شده فقط «کشیده نمی‌شد» و کسی نمی‌فهمید چرا.
- هر مسیر ناموجود، هر فریم دوباره از دیسک پرسیده می‌شد (کش منفی نبود).
- تکسچر هویتش با پیکسل مقایسه می‌شد (بدون revision)، پس «همان تصویر است؟»
  گران بود.

## ۲. قرارداد

```cpp
kimia::AssetManager assets;
assets.addRoot("assets");          // جست‌وجو به ترتیب
assets.addRoot("/sdcard/kimia");

const kimia::MeshData* mesh  = assets.mesh("street/ali.fbx");
const kimia::assets::MeshAsset* model = assets.meshAsset("street/ali.fbx");
const kimia::assets::SkinnedAsset* rig = assets.skinned("kick.fbx");

kimia::AssetManager::Texture tex = assets.texture("street/ali.png");
if (!tex.empty()) use(tex.image, tex.revision);
```

- **کش**: هر مسیر در `std::map` (ترتیب پایدار، اشاره‌گر پایدار) نگه داشته
  می‌شود. بار دوم از حافظه می‌آید.
- **کش منفی**: مسیر خراب هم ذخیره می‌شود؛ فایل گم‌شده هر فریم دوباره
  از دیسک پرسیده نمی‌شود.
- **revision تکسچر**: عددی که فقط وقتی پیکسل‌ها عوض شوند جلو می‌رود.
  رندرگر `revision` را مقایسه می‌کند، نه تصویر را. `invalidate()` بعد از
  تغییر فایل روی دیسک، شماره را جلو می‌برد.
- **مسیر امن**: `resolve()` اول مسیر را همان‌طور که در فایل دنیا ذخیره شده
  امتحان می‌کند (سازگاری با دنیاهای قدیمی: مسیر مطلق، یا نسبی به پوشهٔ
  اجرا)، بعد هر root را به ترتیب. مسیر نسبی **نمی‌تواند** با `..` از
  root بیرون بزند: فایل دنیا داده است و داده نباید کل دیسک را بخواند.
- **گزارش خطا**: `lastError()` متن آدم‌فهم آخرین شکست است («فایل پیدا
  نشد، این پوشه‌ها را گشتم»). خطا مثل خود آبجکت کش می‌شود.
- **«گم‌شده» یعنی فایل نیست**: `missingAssets()` فقط مسیرهایی را فهرست
  می‌کند که فایل‌شان پیدا نشد. فایلی که هست ولی به این درخواست نمی‌خورد
  (OBJ که به‌عنوان اسکلت پرسیده شده، PNG که به‌عنوان مش پرسیده شده) در
  `lastError()` توضیح داده می‌شود ولی وارد این فهرست نمی‌شود: «اسکلت مدل
  نیامده» سؤال دیگری است از «فایل با بیلد نیامده»، و پاسخ‌دادن به دومی با
  اولی، فهرست را روی هر دنیایی که پراپ OBJ دارد بی‌معنی می‌کند.
- **یک کش برای کل نشست**: ویرایشگر (`WorldEditor::assetManager()`) و
  سازندهٔ لیست رسم همان یک نمونه را به کار می‌برند، پس import یک مدل،
  پیش‌نمایش آن و رسمش در هر فریم، یک بار parse می‌شوند.
- **آمار**: `stats()` می‌گوید چند درخواست، چند hit، چند بار واقعاً از
  دیسک خوانده و چند شکست. تست‌ها با همین ثابت می‌کنند کش کار می‌کند؛
  بدون شمارنده، «کش داریم» یک ادعاست.

## ۳. چه چیزی در کش نیست

- `WorldEditor` کش داخلی خودش را دارد (`skinnedCache_`, `assetCache_`)
  چون آن‌ها بخشی از وضعیت دنیا هستند و باید با دنیا بازنشانی شوند.
  یکپارچه‌کردن آن‌ها با `AssetManager` کار بعدی است؛ امروز حلقهٔ فریم
  دیگر هیچ لود مستقیمی ندارد و این همان معیار پذیرش فاز ۲ است.
- صدا: `AudioBuffer` کش نمی‌شود، چون موتور صداها را رویه‌ای
  (`tone`/`thock`) می‌سازد و از دیسک نمی‌خواند؛ `assetscan` جداگانه است.

## ۴. تست‌ها (`Tests/src/AssetManagerTests.cpp`)

| تست | چه چیزی را ثابت می‌کند |
| --- | --- |
| `resolve` روی مسیر نسبی/مطلق/گم‌شده | ترتیب جست‌وجو + پیام خطا |
| `..` بیرون از root | مسیر نسبی نمی‌تواند از root فرار کند |
| کش مش (۳ بار خواندن) | ۱ بار دیسک، ۲ بار hit |
| مش گم‌شده (۳ بار) | ۱ شکست کش‌شده، پیام قابل‌فهم، بدون تلاش دوباره |
| revision تکسچر | پس از `invalidate` شماره جلو می‌رود و دوباره خوانده می‌شود |
| مسیر قدیمی `Tests/assets/x.obj` | سازگاری: مسیر نسبی به پوشهٔ اجرا هنوز کار می‌کند |
